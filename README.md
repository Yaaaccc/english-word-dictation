# 英语单词听写工具

一个给自己用的英语单词听写 / 复习网页，配合扇贝词书与艾宾浩斯复习节奏，材料可导出 PDF 并上传到 GoodNotes。

- 线上地址：<https://yaaaccc.github.io/english-word-dictation/word-dictation.html>
- 本地版：双击 `打开本地网页.bat`，浏览器打开 <http://127.0.0.1:8787/word-dictation.html>

> 最后更新：2026-10-27

---

## 一、两种打开方式，能力不一样

| | 本地版（127.0.0.1:8787） | 线上版（github.io） |
|---|---|---|
| 听写、四选一、打字 | ✅ | ✅ |
| 查词（点例句里的词） | ✅ 本地大词典 77 万条 | ✅ 内置例句词典 1.07 万条 |
| 艾宾浩斯勾选 | ✅ 可勾，自动同步云端 | ✅ 可勾（默认只存本机；配令牌后跨设备） |
| 学习计划改词数 | ✅ 直接写本地 | ✅ 但要先配同步令牌 |
| 生成 PDF / 上传 GoodNotes | ✅ | ⬆️ 点按钮自动跳到本地版执行（本机服务要在跑） |
| 上传状态标记 | ✅ 可点核对云端 | ✅ 只显示 |

**日常建议**：电脑上双击 `打开本地网页.bat` 用本地版；手机 / iPad 用线上版或主屏幕图标。

**本地服务已设开机自启**（2026-10-28）：`启动服务-静默.vbs` 放在用户「启动」文件夹，登录时自动起，不弹窗、不占任务栏。正常不用再手动双击 bat；想重启服务就先结束 `node.exe` 再注销/重启一次。

## 二、功能一览

### 1. 四个练习模式

| 模式 | 怎么练 | 适合 |
|---|---|---|
| **连续播放**（纸上默写） | 自动逐个念，自己在本子上写 | 主练，模拟考场听写 |
| **逐个听写**（打字校对） | 念一个词，键盘拼写，回车判对错 | 检查拼写细节 |
| **回想释义**（四选一） | 看单词选释义，或看释义选单词 | 巩固词义、防遗忘 |
| **提取训练**（先自己想） | 只给一个单词，不给选项也不给例句；先自己把意思调出来，再看答案 | 治「看到选项或例句才想起来」 |

> **四选一默认「选项先遮住」**（2026-11-04）：点一下才显示四个选项。
> 原因见下面「提取训练」——选项一直摆着，人会不自觉地「扫一眼找眼熟的」，练的是匹配不是提取。
> 关掉：设置 →「四选一 · 选项先遮住」。

> **提取训练**（2026-11-04 加）报的不是正确率，是**秒答率（≤1.5 秒）**：
> - ≤1.5 秒 = 秒答（已经自动化，考试里真能用上）
> - 1.5~3 秒 = 想起来了（通路在，但还不够快）
> - >3 秒 = 磨出来的（考试里这个速度等于没有）
> - 点「想不起来」= 没提取到
>
> 键盘：`空格` = 想起来了 · `回车` = 想不起来 · 已判定后 `空格`/`回车` = 下一个。
> 每题结果存浏览器 `localStorage` 的 `dictationRecallStats`（日期 → 单词 → 秒数），换设备不同步。
> 揭示答案时会附一行「同族词」（来自 `word_family.json`），这是第二条记忆线索 ——
> 下次想不起来时，除了「那句例句」，脑子里还能有别的钩子可用。

> 四选一答完的停留时长可在「设置 → 四选一答完停留（秒）」里改：左＝答对、右＝答错；**填 0 = 不自动跳，手动点「下一题」**。改完立刻生效。

连续播放的快捷键：`Enter` 下一个 · `↑↓` / `WASD` 切词 · `R` 重播 · `X` 读例句 · `M` 记下没写出来的词 · 滚轮上下切词。

### 2. 词表与日期

- 词表按日期存（每天 50 个新词），顶部 `‹` `›` 翻日期，右边「今天」一键回到今天
- 练习中切日期 / 换词书 → 当前模式会用新词表**立刻重启**
- 「选词」下拉可跳转，搜索框可过滤

### 3. 查词

随便点例句里的英文单词，弹出小卡片：音标 + 释义 + 「＋ 加入生词本」。
只有点了「加入生词本」才会收录，点词本身只查义、不记账。

**生词本一律存原型**（2026-10-28 起）：点 `threatens` 收进来的是 `threaten`，点 `studies` 收进来的是 `study`。
原型取自词典条目的第 3 项（ECDICT `exchange` 的 `0:` 字段，不是靠词尾猜的）。
同一原型的多个变形只占一条，「查过次数」累加；「只练生词本」、导出 PDF、复制出的也都是原型。
老数据在页面启动时自动归并一次，归并前整本备份在 `localStorage["dictationNewWords.bak.beforeBase"]`。

### 4. 错词本

- 连续播放时按 `M` 标记没写出来的词；同一个词**错过一次就进本子**
- 之后连续两轮都没被标记（或打字模式连续答对两次）自动移出
- 可「只练错词本」、导出错词 PDF、复制词表

### 5. 艾宾浩斯复习

- 右下「今日任务」卡按 +1 / +3 / +6 / +15 天排复习链，学习日制（休息日不计入、自动顺延）
- 行可打勾；电脑上勾完自动推到云端，手机 / iPad 打开就能看到
- **练完一轮会自动勾**：用任一模式（连播 / 打字 / 四选一）练完某一天的词表，任务卡里**那一天对应的行**自动勾上——练 10-27 就勾「10月27日」那行，不碰其他行
  - 本机一定生效；是否同步云端取决于这台设备有没有写权限（本地版 / 配过令牌）
- Dock 的 📅 打开完整日历卡片（今日 + 全程），不再跳独立网页

### 6. 学习计划与材料生成

Dock 的「📋」打开学习计划：改每天多少词 → 「只保存计划」；「生成并上传今天 / 明天」直接出 PDF 推 GoodNotes。

每行右侧的「已上传 / 未上传」：
- 默认读本机的上传记录
- **点它**会真的去 GoodNotes 云端核对（绿=在且页数一致 / 红=记录说传过但查不到 / 橙=页数不符）
- 打开面板时会自动核对最近几天里「记录说传过」的日期

面板下方还有一组 **「上传短文·今天 / 明天」**（2026-11-03 加）：
- 把 `D:\WorkBuddy\daily-article` 里那天已生成的短文 PDF 先推 GoodNotes「短文」文件夹，再发布到 GitHub Pages 的 `articles/`
- **只管上传，不管生成**——短文由每日 20:00 的定时任务或手动写好之后才有 PDF；没有 PDF 会直接报错
- 走的是和「生成并上传」同一条通路：线上点按钮会**跳转**到本地页并带 `?article=today|tomorrow`，
  落地后自动开跑。公网页直连 `127.0.0.1` 会被浏览器的 Local Network Access 整条掐断，跳转是唯一可靠通路
- 后端接口 `POST /api/article-push` + `GET /api/article-status`，脚本是 `push_article_all.py`

### 7. 长篇阅读

Dock 的「📖」打开真题文章列表，点句翻译、划选译、目标词高亮、标记已读。

## 三、数据是怎么流转的

```
扇贝抓取 → 今日单词/YYYY-MM-DD.txt ──┐
                                    ├→ sync-github.js → GitHub 仓库 → Pages（网页读这个）
每日新词例句/YYYY-MM-DD.json  ───────┘

本地生成 PDF → upload_tomorrow.js → GoodNotes「单词」库 + 上传记录.json
                                              ↓
                                    /api/uploaded-dates（本地服务）
                                              ↓
                                         uploads.json（推到仓库，线上读）
```

艾宾浩斯勾选：`ebing-done.json`（仓库根目录）是唯一真源。电脑勾 → 本地服务用 git 凭据写；手机读 GitHub API（Pages 静态文件有 1~3 分钟重建延迟，不能当实时源）。

## 四、已知限制

1. **手机上查词只有 1.07 万条**，人名、地名、品牌（Hershfield、O'Sullivan、NetEase）本来就不收
2. **手机 / iPad 的勾选默认只存本机**（不会同步到其他设备）；在「学习计划 → 配置同步」填一次令牌即可跨设备
3. **上传状态标记读的是记录**，除非您手动点一下核对；记录 ≠ 云端现状

5. 线上 `每日新词例句/` 目录**没有部署**，网页上的例句来自词表 txt 的第 3 列

## 五、踩过的坑（改代码前请先看这一节）

> 每条都是真事，写下来是为了别再犯。

### 1. 一次加载失败，整个会话都废掉
`loadExampleDict()` 的 catch 写成 `EXAMPLE_DICT = {}`，而入口判断是 `if (EXAMPLE_DICT) return ...`——**空对象是 truthy**。于是首次加载失败（872KB 在移动网络下偶发）后，整个会话所有查词都返回空，只有刷新才恢复。表现像"个别词没收录"，很容易误判成词典缺词。
**教训**：「加载失败」和「加载成功但内容为空」必须分开表示，缓存空结果等于把一次网络抖动放大成功能瘫痪。

### 2. 定时器没清，切日期会串题
`stopEverything()` 只清了 `playTimer`，没清 `quizTimer` / `typeFinishTimer`。四选一答完题 1.4 秒内切日期，旧定时器照样把新会话推进到第 2 题。
**教训**：凡是"会自己再跑一步"的 `setTimeout`，启动新一轮前必须清掉；最好再加一个会话代次令牌（`state.gen`），回调先比对代次。

### 3. 干扰项看起来像随机，其实是"随机起点 + 顺序取 3 个"
词池按字母序排，所以三个错误选项必然落在同一字母段——实测 96% 三个干扰项首字母全同、90% 还与答案不同，题目退化成"找不同首字母"。
**教训**：**用数据验证算法，别看代码"感觉像随机"**。随机起点 + 顺序扫描 ≠ 随机抽样。

### 4. 全局 `button:disabled{opacity:.42}` 把答案糊成背景
答题后选项被禁用，整块压到 42% 透明。原先只有单词还能勉强认，加了 12px 释义行后彻底读不了。
**教训**：往按钮里塞新内容前，先查有没有全局 `:disabled` / `opacity` 规则会连坐。

### 5. 面板互斥只做了"自己认识的那两三个"
开长篇阅读再点日历，日历被压在阅读层下面。六个面板散在三个闭包里，各关各的。
**教训**：多浮层系统要有**统一的关闭函数**（`closeSheets(keep)`），别在每个入口各写各的。跨闭包用 `window.__xxx` 暴露。

### 6. 判断"有没有生成"却查了一个从不存在的目录
提醒横幅查 `每日新词例句/<明天>.json` 是否 404，但那个目录从来没同步到仓库——线上连历史日期都是 404，于是每天必弹。
**教训**：**假警报比报错更糟**，会麻痹人。判断依据必须用"页面上真正存在的数据源"（这次改成 `dates.json`），并且拿不到依据时**不提醒**。

### 7. 线上不读本地状态，就一律显示"未上传"
`planLoadUploaded` 开头 `if (!isLocalHost()) return;`，线上读不到记录 → 永远显示"未上传"，比不显示更误导。
**教训**：凡是"本地能读、线上也要显示"的状态，写入口要顺带推一份静态 JSON，不能只判断 `isLocalHost()` 就 return。

### 8. 部署前不 diff 远端，差点把线上功能冲掉
远端 `word-dictation.html` 比本地 v7 多了整套艾宾浩斯任务卡（150 行），因为那批改动只落在部署副本、没回写源文件。直接部署会静默删除。
**教训**：**传之前先 `--dry-run` 比大小，不一致就先拉远端 diff**。源文件（v7 / top.html / tail.html）才是真相，改完必须同步。

### 9. SW 缓存：同一天重建数据文件，用户看不到新版
`sw.js` 对带 `d=` / `v=` **纯数字**参数的数据文件是缓存优先。只换文件不改 URL，浏览器一直读当天第一次的缓存。
**教训**：数据文件重建后要 bump 版本号（`&v=N`，正则只认数字）。词典重建时改 `DICT_VER`。

### 10. 探针写死日期，隔天就误报
`probe_ebingcard.js` 里硬编码"10月26日 / 第 18 天"，第二天跑就红 2 项。
**教训**：探针的预期值要从数据源现算，不能写死。

### 11. 全大写兜底把 `pets` 解析成 `PETS`
查词降级链会给短词试全大写（UK / DNA / Mr 需要），但长词也走就会命中 `PETS`（公共英语等级考试）这种缩写词条。
**教训**：兜底规则要有**适用范围**（长度 ≤4），否则会引入荒谬的结果。

### 12. 玻璃卡片顶上一条扎眼的白线
`.glass` 的 `border-top`（白 .55）和内高光 `inset 0 1px 0`（白 .65）叠在一起，深色壁纸下近乎不透明，左右却只有边框。
**教训**：视觉"bug"往往不是布局问题，而是**两条半透明叠加**。查 computed style 比猜快。

### 13. 公网页跨域调本机，被 Local Network Access 整条掐断

给 `server.js` 加了完整的 CORS 头（`Access-Control-Allow-Origin`、`Allow-Private-Network`、`OPTIONS 204`），以为线上页就能直接 POST 到 `http://127.0.0.1:8787` 了。实测（headless Edge + CDP，`probe_pna_diag.js`）：

| 场景 | 结果 |
|---|---|
| 本地页（同源）→ 8787 | ✅ 200，body 正常 |
| 线上页 https → `127.0.0.1` **cors** | ❌ Failed to fetch |
| 线上页 https → `127.0.0.1` **no-cors** | ❌ Failed to fetch |
| 线上页 https → `localhost` cors | ❌ Failed to fetch |

**关键判据**：连 `no-cors` 都失败 ⇒ 不是 CORS 头的问题，是**网络层权限**（Chrome/Edge 的 Local Network Access，公网 secure context 访问本机回环需要用户授权，headless 下直接拒绝）。配多少响应头都没用。

**结论与做法**：改走**页面导航** —— `location.href` 跳转不是网络请求，不受该策略约束。实测 `probe_nav_allowed.js` 跳转后 `origin` 正确变成 `http://127.0.0.1:8787`、DOM 正常，方案成立。
**教训**：跨域问题的第一诊断动作应该是**对比同源与 no-cors**。同源通 + no-cors 不通 = 浏览器网络层策略，别再在 CORS 头上使劲。`server.js` 里那段 CORS 代码目前是死代码，留着备用（浏览器策略放松时可直接复用），但不要误以为它在生效。

### 14. 改「存储口径」只改写入不够，老数据会留下来打脸
生词本从「按点到的词形存」改成「一律存原型」时，如果只改 `addToNewBook` 的 key，
**用户现有的 threatens / studies 条目照样躺在列表里**，看起来像没改成功。
更阴的是反向问题：新代码用 `threaten` 判断「在不在本子」，老条目 key 是 `threatens` ⇒ 判定为「不在」，
于是点一下又新建一条，越用越乱。

**做法**：口径变更必须配一次**启动时的幂等迁移**——遍历本子，`base` 有值就并到原型，hits 相加，
`changed` 为假时一个字节都不写；迁移前把整本备份到另一个 key，随时能还原。
**判据**：探针里要同时验「老数据已消失」和「新写入用原型」，只验后者会漏掉一半。

### 15. 「一条线」排了三轮修不到：检测点被自己的按钮污染 + 没法确认用户看的是哪版
用户三次截图报「卡片顶部一条线」。第一、二轮按边框/内高光方向改 CSS，没用。第三轮逐像素扫描才发现两个致命坑：
1. **检测点被自己的按钮污染**：卡片右侧的白色「停止」按钮顶边恰好也在关注的高度上，宽占比 4.6% × 亮度差 180 ≈ +8.4，和「疑似接缝」的强度一模一样。排除按钮后左侧纯背景区差异只有 0.38 级（噪声）——**页面里根本没有线**。
2. **无法远程确认用户看的是哪一版**：线上 md5 与本地一致，但用户浏览器/PWA/WebView 的缓存、扩展（深色模式类会给半透明元素注入背景，正好拉出直线）都可能让用户看到"不存在的线"。
**教训**：① 量化检测先排除高对比 UI 控件（按钮/芯片/文字），否则均值全被它们主导；② 远程排查 UI 前先在页面上放一个**可见构建版本号**（本次加在快捷键卡底部），报问题第一句先对版本；③ 改三次都没命中的"视觉 bug"，要停下来怀疑"用户看到的代码和我改的不是同一份"。

### 16. 「轻休顺延」用错了基准，一跳跳过 100 词
2026-11-02 早上用户说"单词感觉不对"。查下来：轻休 4 天（10-29~11-01）后，网页给的是 `identical` 开头、**70 个词**，而 10-28 实际停在 `pigeon`（词库第 1049 个）。
**根因**：11-01 做顺延时，把「原 10-29 的内容」按 **10 月早期那套 70 词/天的旧批次** 算（那套里 10-29 = 第 6 天 = `identical` = 第 1150 个词）；但 10-24 起实际跑的是 **50 词/天**（10-28 是第 5 批，尾词 `pigeon` = 第 1049 个）。两套口径混用，中间 `sphere…remote` 整整 **100 词**被静默跳过。
**教训**：
- 顺延前先量「**上一批的尾词索引**」，不要用「日期 → 第几天」去推算。索引是物理事实，天数是推算值，推算链条一断就错。
- 仓库里同时躺着两套批量词表（70 词/天旧批 + 50 词/天新批）时，`dates.json` 命中哪天纯看运气。**换口径必须把旧批次全量覆盖，只改当天等于埋雷**。
- **词数本身就是探针**：旧批次 70 词、新批次 50 词，页面上一眼看到 70 就知道读的是错文件。校验时同时核对「首词 + 尾词 + 词数」三件套。

### 17. 本地与线上**双向**分叉：两边各丢一块功能

### 18. 提示语治不了习惯，只有「路走不通」才治得了

**现象**：四选一页面一直写着「先回想词义再选择」，但实际动作是「直接扫四个选项找眼熟的」，练了几个月仍然「看到选项才想起来」。

**根因**：提示语只作用于「想不想做」，不作用于「能不能做」。选项一直摆在眼前，扫一眼是零成本的最优动作 —— 人的默认行为会被**环境**塑形，不会被**文案**塑形。

**教训**：要改行为，改**动作成本**，别改**文案**。
- 想让人「先想」→ 把选项遮掉（多一步点击），而不是加一句「请先想」
- 想让人「不看例句」→ 出新题时先 `clearExamplePanel()`，而不是提醒「别看例句」

同理，任何「用户总是不按提示做」的问题，先问一句：**是不是不按提示做更省力？**

### 19. 三份源文件会「一起落后」，build 一次就把新功能全部覆盖掉

**现象**：2026-11-05 要给页面加「一键轻休」，先跑了一次 `node _v5_parts/build.js`，产物从 468135 字节掉到 463977，**11-04 刚做的「提取训练」整个消失**。

**根因**：11-04 那次只改了产物 `word-dictation.html`，三份源都没回写：
- `word-dictation-v7.html`（正文 + 业务 JS）
- `_v5_parts/top.html`（75 行 CSS —— 提取训练的样式）
- `_v5_parts/tail.html`（`MODE_IDX` / `START_FWD` 里的 `recallModeBtn`）

build 的规则是「v7 的 style 换 top、v7 的尾部 script 换 tail」，所以三处任何一处旧，产物都会退回去。

**教训**：
1. 判断有没有分叉，不要比 mtime，要 **grep 关键词**：`grep -c recallModeBtn word-dictation.html word-dictation-v7.html _v5_parts/tail.html`，有一处是 0 就是分叉。
2. 修复顺序：**用线上完整版反向补齐 top / tail → 再拿完整版当 v7 → build → 三份 md5 必须相同**。md5 相同才算闭环，否则下次 build 还会掉。
3. 只要打算改页面，先跑一遍这个闭环，再动手。

### 20. 批量改名脚本必须只对「差集」动手，否则不幂等

**现象**：一键轻休第一版，日期 `2026-11-05` 明明已经在轻休列表里（只打了句「无需改动」），脚本仍然把 11-06~11-19 整条链又往后推了一天，28 个文件位移。

**根因**：词表顺延那步判断用的是 `dates`（本次请求传入的日期），而不是 `new_dates`（真正新加进轻休列表的）。「已经是轻休」只 log 了一句，没 `return`，后面照跑。

**教训**：凡是「按日期批量改名」的操作，第一步先算差集，后面所有动作只对差集生效；重复执行必须做到「移动 0 个文件」。修完要专门验一次幂等（同一参数再跑一遍，看日志里是不是 `共移动 0 个文件`）。

### 21. 「列表 0 条」的真凶是就绪判断，不是选择器，也不是后台标签

**现象**：`upload-to-goodnotes.js --list` 报「0 个条目」、`--delete` 报「没找到」、上传偶尔报「找不到新建按钮」。截图看页面上明明有 53 张卡。

**走过的弯路**（都无效，别再重复）：
1. 换选择器：`aria-label` → `.lib-file` → `.lib-file-name`。这些元素其实都在。
2. 怀疑后台标签被冻结：`createBackgroundTab` 改成 `createTarget` + `activateTarget`。不是这个原因。
3. 怀疑尺寸过滤：去掉 `getBoundingClientRect` 的宽高判断。也不是。

**真因**：`LIST_CARDS_JS` 的 `ready` 用的是「能找到『新建』按钮」。而**骨架阶段这个按钮就已经在 DOM 里了**，卡片还没渲染，于是 `waitFor` 第一次轮询就通过，拿到空列表，后面所有判断都以为文件夹是空的。

用 `GN_DEBUG_LIST=1` 打出原始返回才看见：`{"ready":true,"cards":[],"total":252}` —— 完整页面约 1800 个元素，252 说明还在骨架。

**修法**：
```js
ready: cards.length > 0 || all.length > 900
```
（≥900 视为页面已画完，允许空文件夹；否则继续等）

**另一件事**：无头 Edge 连续跑久了（实测 27 分钟）会进「无法加载笔记，请重试」状态，页面报错、新建按钮变灰。此时**所有脚本都会读到空列表**，看起来像脚本坏了。判断方法很简单：截一张图看页面，别急着改代码。
